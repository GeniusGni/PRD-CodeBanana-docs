## 项目与聊天模式

CodeBanana 中的每个项目都有对应的群聊，并提供三种不同的聊天模式，以满足不同的协作需求。

### 聊天模式

每个项目群聊都包含以下三种模式：

#### **Team Agent**

Team Agent 模式面向团队环境中**共享且受控的 AI 协作**。团队成员不再分别与各自独立的助手交互，而是共同使用一个**项目级 Agent**。该 Agent 基于共享代码库、共享上下文和共同目标开展工作。

该模式确保由 AI 驱动的变更在整个团队中始终**可见、协调且目标一致**。

#### **什么是 Team Agent**

Team Agent 是项目的**集中式 AI 协作者**：

- 基于**完整项目上下文**工作，包括仓库、文件、讨论和历史记录
- 作为编码、重构、调试和任务自动化的**共享执行层**
- 确保所有由 AI 生成的变更在团队工作区中**透明且可追溯**

Team Agent 不同于个人 AI 工具，它并非私密工具。每次交互都会成为**项目共同状态**的一部分。

#### **协作方式**

为保持一致并避免冲突，Team Agent 采用**受控交互模式**：

- 同一时间只能有一位团队成员与 Agent 交互。默认情况下，只有**项目 Owner** 和**项目 Admin** 可以与 Team Agent 交互
- Agent 空闲时，项目 Admin 无需 Owner 手动批准即可取得控制权

其他成员希望使用 Team Agent 时：

- 必须向 Owner **申请 Presenter 权限**
- 获批后，**只有该成员获得与 Agent 交互的权限**
- 在此期间，其他所有成员都无法使用，直到控制权被重新分配

活跃会话期间：

- Agent 根据当前用户的指令执行任务
- 所有变更都会**立即对团队可见**
- 用量计入**项目 Owner**

该模式类似协同编辑中的“单写入者”系统，确保 AI 操作**按顺序执行、可审查且不会相互冲突**。

#### **排队与停止**

多位用户向 **Team Agent** 发送消息时，消息会通过共享队列处理。

**排队行为**

- 所有消息按照**发送时间顺序**处理
- 整个项目共用**一个 Team Agent 队列**
- 同一用户连续发送的多条消息会依次排到**队列末尾**
- 队列上限为 **50 条消息**
- 队列已满时，用户会看到：**“Agent is busy, please try again later”**
- 一条消息处理完成后，下一条排队消息会自动开始
- 如果撤回排队中的消息，其位置会被释放，后续消息自动前移

**队列可见性**

- Team Agent 视图会显示当前队列状态，包括仍在等待的消息数量
- 项目中的所有成员都能看到当前队列数量

**谁可以停止消息**

- **消息发送者**可以停止自己的消息，无论消息正在运行还是仍在队列中等待
- **项目 Owner** 可以停止 Team Agent 队列中的任何消息
- 其他成员不能停止由其他用户发起的消息

**停止后会发生什么**

- 已经生成的内容会**保留**
- 队列位置会立即释放
- 下一条排队消息会自动开始
- 用户可以发送新消息，新消息会进入队列末尾

#### **Agent 模式**

Agent 模式定义 Agent 与项目的交互方式，覆盖从只读辅助到直接执行代码的不同场景。

- **Ask-only** 只读模式。Agent 回答问题并提供指导，但不会修改任何文件。
- **Coding** 执行模式。Agent 可以直接在项目中编写和编辑代码。
- **CodeBanana（CB Optimized Model）** 针对项目级任务增强，并预装部署等能力。
- **Claude Code（Claude Native Model）** 与 Claude 原生体验保持一致，需要更明确的提示和用户指导。

#### **Private Ask**

Private Ask 模式（原 My Agent / Private Agent）在项目中提供**个人 AI 辅助**，用户可以独立工作，不会影响共享工作流。

**什么是 Private Ask**

一个独立于 Team Agent 运行的私密用户级 Agent。

适用于：

- 提问
- 规划任务
- 探索想法

所有交互均与**团队的活跃工作流隔离**。

**使用特征**

- 主要以 \*\*Ask 模式（只读）\*\*运行
- 可以与 Team Agent 会话**并行使用**
- 不修改共享项目
- 用量根据项目的计费上下文归属

#### **排队行为**

Private Ask 使用**个人队列**，而不是共享的 Team Agent 队列。

- 只有你自己的消息会进入同一队列
- 你的 Private Ask 队列与其他用户完全隔离
- 消息仍按照发送时间顺序处理
- 停止消息只会影响你自己的 Private Ask 会话

Private Ask 让用户能够保持个人工作效率，同时确保团队级协作**有序且无冲突**。

### **Discussion**

Discussion 模式是面向整个团队的**沟通空间**，用于开放协作与协调。

**什么是 Discussion**

- 团队成员讨论想法、对齐需求和协调工作的共享聊天频道
- 作为**以人为先的协作层**，与直接执行工作流相互独立
- 团队也可以根据需要在 Discussion 中启用内置协调层

**使用特征**

- 所有成员都可以**自由参与**
- 支持**实时讨论、反馈和决策**
- 对话对整个团队可见，并保留为项目上下文的一部分
- 默认情况下，Discussion 专注于沟通，而不是直接执行

#### **Discussion Coordinator（DC）**

Discussion 内置 **Discussion Coordinator（DC）**。DC 在群组讨论中充当协调者，而不是直接执行任务的 Agent。

它可以：

- 理解当前讨论上下文
- 跟踪参与者和对话进度
- 帮助总结和整理讨论内容
- 当用户在讨论中提及其他 Agent 时，将请求转交给相应 Agent

#### **DC 如何工作**

DC **默认保持静默**。它不会主动打断讨论，只有被明确激活时才会响应。主要有两种激活方式：

- **@mention DC**
- **在 Discussion 中回复 DC 的消息**

**激活路径**

- 在 **Team Agent** 聊天框中提及 DC，会通过 **A2A** 激活，适用于多 Agent 协作
- 在 **Discussion** 聊天框中提及 DC，会直接激活它来协调群组讨论
- 在 **Discussion** 中回复 DC 发送的消息，会再次激活 DC

**回复限制**

- 只有回复带有 **Discussion** 标签的消息才能重新激活 DC
- 回复其他 Agent 的消息**不会**激活 DC

激活后，如果 DC 判断当前话题仍需后续协调，它可以继续参与。协调任务完成后，DC 会自动恢复静默模式。

#### **DC 的边界**

DC 是协调者，而不是执行 Agent。它**不会**直接：

- 编写代码
- 修改文件
- 创建项目内容
- 在工作区中执行写入操作

DC 会通过以下方式推动讨论：

- 整理上下文
- 明确请求
- 根据需要将工作转交给合适的 Agent。这样，Discussion 可以作为轻量级协调层，同时确保实际执行发生在正确的 Agent 模式中。
